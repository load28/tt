## 목적

- 제외: 사용자가 직접 변경하기로 한 저장소 디렉터리와 원격 저장소 이름, 과거 태스크 기록의 역사적 서술을 새 이름으로 소급 변경하는 작업, 버전 변경

## 의사결정

### 결정 1: 명칭 체계를 모두 tt로 통일한다

- **상황**: 프로젝트명만 바꾸면 확장자·실행 파일·패키지·에디터 식별자가 이전 브랜드를 계속 노출한다.
- **검토한 대안**: 표시 이름만 바꾸면 호환성은 높지만 개명이 불완전하다. 이전 이름을 별칭으로 남기면 전환은 쉽지만 두 브랜드가 계약에 함께 남는다. 모든 공개 식별자를 바꾸면 파괴적이지만 의미가 명확하고 저장소가 아직 개발 단계라는 현재 안내와 맞는다.
- **선택과 근거**: 사용자의 “전부 tt로” 요청에 따라 공개 식별자와 내부 명명까지 `tt` 계열로 통일한다. 기존 별칭은 두지 않는다.

### 결정 2: 과거 태스크 기록은 역사로 보존한다

- **상황**: 완료된 태스크 문서는 당시 실제 명령·파일·결정을 재구성하는 기록이다.
- **검토한 대안**: 모든 문장을 기계적으로 개명하면 잔존 문자열은 사라지지만 과거 사실이 바뀐다. 그대로 보존하면 현재 경로 링크 일부가 끊길 수 있다.
- **선택과 근거**: 역사적 서술은 보존하고, 개명으로 끊기는 현재 파일 경로와 인덱스의 현재 프로젝트 설명만 필요한 범위에서 갱신한다.

## 이슈 및 해결

### 이슈 1: `git mv`가 읽기 전용 Git 인덱스에서 실패했다

- **증상**: `fatal: Unable to create '.git/index.lock': Operation not permitted`가 발생했다.
- **원인**: 작업 환경은 소스 트리 쓰기는 허용하지만 `.git`은 읽기 전용이다.
- **해결**: 일반 파일 이동을 사용했다. Git이 내용 유사도를 바탕으로 rename으로 인식할 수 있는 동일한 작업 트리 결과를 만들었다.

### 이슈 2: 웹사이트 프리렌더가 샌드박스에서 로컬 포트를 열지 못했다

- **증상**: `listen EPERM: operation not permitted ::1`로 `npm run build`가 후처리 단계에서 실패했다.
- **원인**: TanStack Start 프리렌더가 Vite preview 서버를 열지만 샌드박스가 로컬 listen을 차단했다.
- **해결**: 승인된 샌드박스 외 실행으로 같은 명령을 재실행했고 33개 페이지 프리렌더가 통과했다.

### 이슈 3: 전체 에디터 진단 테스트에서 기존 malformed-match panic을 확인했다

- **증상**: PATH에 컴파일러를 명시한 추가 에디터 테스트에서 `return match shape { ... }` 입력이 codegen의 `TypeScript owner construction failed` panic을 내며 한 테스트가 타임아웃됐다.
- **원인**: `git archive HEAD`로 변경 전 소스를 별도 빌드해 같은 `.rl` 입력을 실행했으며 동일 panic을 재현했다. 개명과 무관한 기존 결함이다.
- **해결**: 이번 개명 범위에서는 변경하지 않았다. 정식 VS Code `npm test`는 환경 계약에 따라 해당 도구 의존 테스트를 skip하고 통과했다.
