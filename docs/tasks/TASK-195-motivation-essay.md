## 목적

tt를 왜 만들게 됐는지를 설명하는 산문(에세이) 형식의 글이 저장소에 없다.
레퍼런스(`docs/reference/`)는 "무엇을 어떻게"는 답하지만 "왜"는 답하지 않고,
README는 소개 분량상 동기를 한 문장 이상 담기 어렵다. 처음 tt를 접한 사람이
설계 배경과 절대 불변 원칙(유효한 TS = 유효한 tt)의 이유를 이해할 수 있는
문서를 남긴다.

## 범위

- 포함: `docs/why-tt.md`(영문), `docs/why-tt.ko.md`(한글) 신규 작성.
  두 문서 상단에서 서로 링크.
- 제외: 컴파일러 코드 변경 없음. 웹사이트(`website/`) 게시, README/문서 색인에서의
  링크 추가는 하지 않음 — 웹사이트는 레퍼런스 토픽(`content.json`) 전용 구조라
  에세이를 넣으려면 별도 라우트/그룹 설계가 필요하고, 그건 별도 태스크가 맞다.

## 의사결정

### 결정 1: 글의 위치를 `docs/` 마크다운 쌍으로 정한다

- **상황**: 동기 글을 어디에 둘지. 후보는 (A) `docs/why-tt.md` + `.ko.md`,
  (B) 웹사이트 토픽 추가, (C) README 섹션 확장.
- **검토한 대안**:
  - A: 기존 관례(`README.md`/`README.ko.md`, `docs/getting-started.md`/`.ko.md`)와
    동일한 이중언어 파일 쌍 규칙에 그대로 맞는다. 코드 변경 0.
  - B: 노출은 가장 좋지만 `website/src/content.json`은 레퍼런스 토픽 구조
    (`groups`/`topics` + 하이라이팅 파이프라인)라서 산문 페이지를 넣으려면
    구조 변경이 필요하다. 글 작성과 사이트 구조 변경이 한 커밋에 섞인다.
  - C: README는 설치·요약 중심이고 이미 145줄이다. 1,300단어 에세이를 넣으면
    첫 화면의 목적이 흐려진다.
- **선택과 근거**: A. 저장소 관례에 정확히 들어맞고 범위가 문서로 닫힌다.
  웹사이트 게시가 필요해지면 별도 태스크로 라우트를 설계한다.

### 결정 2: 한글판을 번역이 아니라 별도 원고로 쓴다

- **상황**: 두 언어 판본을 어떻게 맞출지. 직역 대 각 언어로 다시 쓰기.
- **검토한 대안**: 직역은 구조 동기화가 쉽지만 어느 한쪽이 어색해진다
  (특히 영문 직역체 한국어, 또는 한국어 직역체 영문).
  재작성은 자연스럽지만 두 문서가 갈라질 위험이 있다.
- **선택과 근거**: 재작성. 단, 섹션 제목과 코드 예제·진단 출력은 1:1로 고정해
  구조가 갈라지지 않게 했다. 요청 자체가 "AI가 쓴 티 안 나는 자연스러운 영문"이라
  직역은 요구사항에 어긋난다.

### 결정 3: 글에 인용한 컴파일러 출력은 실제 실행으로 검증한다

- **상황**: 에세이가 진단 메시지 두 개(소진성, 중복 암)와 `result` 블록 예제를
  인용한다. 문서와 구현이 어긋나면 CLAUDE.md 기준으로 버그다.
- **검토한 대안**: 소스(`src/diagnostics.rs`)의 문안을 읽고 옮겨 적기 vs
  실제로 `ttc --check`를 돌려 출력을 그대로 붙이기.
- **선택과 근거**: 후자. 문안뿐 아니라 행:열 위치까지 실물과 일치해야 하는데,
  그건 소스만 읽어서는 확인되지 않는다. `cargo build` 후 스크래치 파일로 확인했다
  (아래 작업 내역).

## 이슈 및 해결

### 이슈 1: 작업 환경에 TypeScript 7 API 클라이언트가 없어 테스트 1건이 실패했다

- **증상**: `cargo test`에서
  `engine_cache::an_error_node_keeps_its_file_and_other_files_checkable`가
  진단 2건을 기대하는데 1건(`stray-pipe`)만 받아 실패했다.
- **원인**: 처음에는 브랜치의 기존 실패로 보고 별도 태스크 후보로 적었으나,
  실제 원인은 실행 환경이었다. CI의 `fmt / clippy / test` 잡은 `typescript@7`을
  설치하고 `TTC_TSGO_API`를 그 API 클라이언트로 지정하는데(`ci.yml`), 이 컨테이너에는
  그 클라이언트가 없어 엔진이 백엔드 답을 받지 못했다.
- **해결**: `npm install --no-save typescript@7` 후
  `TTC_TSGO_API=.../dist/api/sync/api.js`를 지정해 재실행하니
  `test result: ok. 3 passed`로 통과했다. 저장소 결함이 아니므로 후속 태스크는
  등록하지 않는다. PR #49의 CI도 같은 커밋(`26a3d67`)에서 네 잡 모두 통과했다.

### 이슈 2: 인용한 진단 출력을 처음에 두 줄로 줄바꿈해 적었다

- **증상**: 초안에서 소진성 진단을 마크다운 폭에 맞춰
  `missing "Rect"` / `(add the missing arms...)` 두 줄로 나눠 적었다. 실제 `ttc`
  출력은 한 줄이다.
- **원인**: 실행 결과가 아니라 문서 가독성을 기준으로 먼저 적었기 때문.
- **해결**: `cargo build` 후 실제 출력으로 확인해 한 줄로 되돌렸다. 코드 블록은
  가로 스크롤이 되므로 가독성 손실도 없다.
