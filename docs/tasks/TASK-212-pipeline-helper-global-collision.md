## 목적

파이프를 사용하는 비모듈 출력 파일 여러 개를 같은 TypeScript 프로그램에서 검사할 때
파일별 헬퍼 선언이 전역에서 충돌하는 문제를 제거한다.

## 범위

- 포함: 프로젝트 공용 파이프 런타임, CLI·번들러의 단일 모듈 제공, 다중 파일 회귀 테스트, 관련 설계 문서
- 제외: 파이프 비동기 의미 변경

## 의사결정

### 결정 1: 프로젝트 공용 런타임 모듈을 도입

- **상황**: 독립 파일 방출 계약을 유지하면서 전역 스크립트의 중복 선언을 허용해야 한다.
- **검토한 대안**: 파일별 고유 이름은 공개 `compile()` API에서 다른 파일의 사용자
  식별자를 알 수 없어 충돌 부재를 증명할 수 없다. `var` 함수식은 전역 가변 바인딩을
  남긴다. 호출 자리 함수식은 전역을 없애지만 실행할 때마다 함수 객체를 만든다.
- **선택과 근거**: 파이프 출력이 `@tt/runtime`의 `$tt_ap`·`$tt_fl`을 import한다.
  CLI는 출력 공통 루트의 `tt/runtime.ts`를 한 번만 만들고 각 파일에는 상대 import를
  쓴다. 번들러는 같은 bare specifier를 가상 모듈 하나로 제공한다. ES 모듈 캐시 계약상
  헬퍼 함수 객체는 프로젝트 실행에서 한 번만 생성되며 전역 바인딩도 없다. head와
  step은 기존처럼 함수 인자로 남아 왼쪽부터 평가되고 문맥 타입과 `await` 위치가
  유지된다.

## 이슈 및 해결

### 이슈 1: `var` 재선언은 충돌 증상만 피한다

- **증상**: 동일한 `var $tt_ap` 선언은 TypeScript 오류 없이 합쳐진다.
- **원인**: 모든 파일이 하나의 전역 가변 바인딩을 계속 공유한다.
- **해결**: 전역 선언 자체를 제거하고 프로젝트 공용 ES 모듈로 헬퍼 소유권을 옮겼다.
