## 의사결정

### 결정 1: 입력 줄바꿈은 보존하고 VSIX 시간 구성 요소만 정규화한다

- **상황**: Windows checkout의 CRLF 때문에 Cargo 버전을 찾지 못했고, 자정 직후의
  `HHMMSS`가 `0`으로 시작해 VSIX의 숫자형 SemVer 구성 요소로 인정되지 않았다.
- **검토한 대안**: checkout 줄바꿈 강제 / 스크립트에서 LF와 CRLF 모두 허용,
  VSIX 버전 형식 교체 / 기존 형식의 마지막 구성 요소를 정수 문자열로 변환.
- **선택과 근거**: 스크립트가 플랫폼별 입력을 직접 수용하면 Git 설정에 의존하지 않는다.
  기존 날짜 기반 버전 구조를 유지하면서 숫자형 구성 요소의 선행 0만 제거한다.

## 이슈 및 해결

### 이슈 1: 릴리스 전용 잡이 PR CI 이후 실패했다

- **증상**: Windows에서 `Cargo.toml ttc version was not found`, VSIX에서
  `Invalid extension "version": "0.260826.001724"`가 발생했다.
- **원인**: 버전 정규식이 LF만 허용했고, VSIX 시간 구성 요소가 선행 0을 포함했다.
- **해결**: 기존 줄바꿈을 보존하면서 LF와 CRLF를 모두 인식하게 했다. VSIX 버전의
  마지막 구성 요소는 정수 변환으로 선행 0을 제거했다.
