# TASK-458: Reject a default-exported variant and locate generated-parse failures at their construct

- **Status**: Complete
- **Started**: 2026-09-28
- **Completed**: 2026-09-28
- **Commit**: —

> TASK-671 reclassifies a projection parse that stops at the first byte of
> an outermost placeholder as `source-not-typescript` at the construct:
> `const x = variant Dir { Up, Down }` now reports that, at the variant,
> instead of `lowering-plan-failed`. Decision 2 still holds for a failure
> inside a placeholder.

## Purpose

`export default variant Dir { Up, Down }` failed with `lowering-plan-failed: the generated TypeScript for it does not parse: Expression expected`. The error was anchored at a different variant (`Shape` on line 1 when one was declared first) or at `export default ` when the variant was alone, so the report named neither the rule nor the construct.

## Scope

- Included: The parser's recognition of `export default variant Name { ... }`, a new `variant-default-export` diagnostic with `ttc explain` text and a mapper wire number, and the source anchor of every `lowering-plan-failed` report caused by a parse failure inside compiler-generated projection text.
- Excluded: Supporting default-exported variants, collecting a default import binding for cross-file exhaustiveness, and new diagnostics for a `variant` written in expression position (`const x = variant Dir { ... }`), which still report `lowering-plan-failed` but now at that variant.

## Decisions

### Decision 1: `export default variant` is not part of the language

- **Context**: `docs/ai/tt.md` documents `export variant`, `declare variant`, and `export declare variant`, and says a variant emits a type alias and a constructor object, both exported when `export` is written. It never mentions a default export. The import collector records named and namespace bindings only (`TtImportNames` says "tt variants are named exports").
- **Alternatives considered**: Supporting it by emitting `type Dir = ...; const Dir = {...}; export default Dir;`. With the pinned `tsc`, a default export of a name with a type and a value meaning exports both: `import Dir from "./dir.js"` accepts `const d: Dir = Dir.Up` and rejects `{ kind: "Left" }` with TS2322, while `export default type X = number;` is TS1005. So the emitted form works, but the feature would also need the default binding in the import clause parser, the CLI, engine, and content-mapper extern collection, sidecar declarations, and editor symbol handling, all for a surface the language has not defined.
- **Decision and rationale**: Reject it with a located tt diagnostic. The declaration is a complete `variant` behind `export default`, which is never TypeScript, so claiming it does not affect passthrough. The error is at `default` and carries an edit that deletes `default ` so the variant becomes a named export. A declaration that does not parse as a variant keeps its `malformed-variant` report instead. The recovery node covers the whole statement as an exported declaration, so the typed path still reports independent type errors in the file.

### Decision 2: Anchor a generated-parse failure at the innermost placeholder that holds the failing byte

- **Context**: `lowering_plan_with` reported every `ProgramSyntaxError` except `SourceNotTypeScript` at `primary_source()`, the file's first tt node. For a variant placed where TypeScript expects an expression, the parse stops inside that variant's `const $tt_syntax_item_N = 0;` placeholder, whose projection segment already records the variant's source span.
- **Alternatives considered**: Keeping the first-node anchor and only fixing the default-export case would leave every other generated-parse failure misattributed (for example `f(variant Dir { ... })` after an unrelated variant).
- **Decision and rationale**: `parse_failure_at` now resolves a failure in generated bytes to the smallest `Placeholder` segment containing it and stores that source span in `ProgramSyntaxError::Parse`. `lowering_plan_with` reports that span and falls back to the first node only for failures that carry no placeholder.
