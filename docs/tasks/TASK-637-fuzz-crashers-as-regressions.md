# TASK-637: Replay fuzz crashers as permanent regressions, and mutate the case corpus

- **Status**: Complete
- **Started**: 2026-09-30
- **Completed**: 2026-09-30
- **Commit**: see `git log --grep TASK-637`

## Purpose

The two fuzz targets (TASK-223) only run under `cargo +nightly fuzz`, by
hand, and a crash they find leaves nothing behind in `cargo test`. Go's fuzz
model, which typescript-go uses for its parser, keeps every crash input in
the repository and replays it on every test run. This task adopts that model
and adds a deterministic mutation pass over the case corpus, so the
"half-typed buffer" states an editor produces are exercised on every pull
request.

- Included: `fuzz/src/lib.rs` (the target bodies, shared), the two
  `fuzz/fuzz_targets/*.rs` wrappers, `fuzz/Cargo.toml`, `fuzz/Cargo.lock`,

- Excluded: fixing the crashes found (TASK-621 and TASK-622 hold the fixes

  typed (TypeScript-backed) pipelines, which TASK-639 covers for the editor.

## Decisions

### Decision 1: Share the target bodies by including one file, not by a crate dependency

- **Context**: The stable tests must call the exact code `cargo fuzz` runs.
  The fuzz package has its own workspace and depends on `libfuzzer-sys`.
- **Alternatives considered**: (a) A `ttc::fuzzing` module in the library:
  puts test scaffolding and an `arbitrary` dependency into the public
  crate. (b) A dev-dependency on the `ttc-fuzz` package: a dependency cycle
  (`ttc` dev-depends on a package that depends on `ttc`), two copies of the
  crate in the test, and `libfuzzer-sys` in every `cargo test` build.
  (c) One source file, `fuzz/src/lib.rs`, that is the `ttc_fuzz` library of
  the fuzz package and is included by `tests/fuzz_regressions.rs` with
  `#[path]`; `arbitrary` becomes a dev-dependency of `ttc`.
- **Decision and rationale**: (c). The wrappers in `fuzz/fuzz_targets/` are
  one line each, `TARGETS` names every target, and a directory under
  `fuzz/regressions/` that names no target fails the replay.

### Decision 2: The pipelines are the ones a consumer reaches without TypeScript

- **Context**: The old `compile_any_bytes` ran `analyze` and `compile`
  only. Editors reach more: the emit map, the engine's recovering projection,
  and the text-only requests (semantic tokens, hints, declarations, the tt
  symbol, tt completions and keywords at the cursor). `ttc::compile` also
  asks the working directory's TypeScript to annotate generated storage when
  it finds one; in the test, the repository's `node_modules` made one mutant
  take a second and serialised the workers on the TypeScript host.
- **Alternatives considered**: Keep `compile` with its defaults (the pass
  would depend on the checkout having `npm ci`, and on process scheduling);
  run the typed engine per mutant (seconds each).
- **Decision and rationale**: `every_pipeline` runs `check_report` and
  `analyze` with the default options (ttc's own exhaustiveness and `val`
  judgments, as `ttc --check`), `compile` and `compile_report` with
  `defer_to_checker` (as the engine does, which is also what the fuzz
  directory without a toolchain always did), `compile_report` without the
  output self-check, `emit_mapped_with_kind`, `compile_projection_report`
  with the engine's options (`src/engine/projection.rs`), and the six
  text-only editor requests at the end of the text. `generated_tt_compiles`
  keeps its claims: `analyze` reports no error, and `compile` succeeds twice
  with the same output.

### Decision 3: An honest expected-failure list, keyed by the crash

- **Context**: Two known ICEs are fixed on a paused branch and the pass found
  a third. The replay must stay green without hiding them, and must notice
  when a fix lands.
- **Alternatives considered**: `#[ignore]` the inputs (nothing notices a
  fix); keep them out of the repository until fixed (the reproduction is
  lost); key the list by panic line (moves with every unrelated edit).
- **Decision and rationale**: `fuzz/regressions/expected-failures.txt` lists
  `<target>/<file>`, the task, and the crash signature: the panicking file
  and the first line of the message with numerals masked. The replay fails
  when an unlisted input crashes, a listed one does not, or a listed one
  crashes with another signature; the mutation pass tolerates only listed
  signatures. Applying TASK-621's one-line fix locally made the replay fail
  with "arm-guard-not-written.tt no longer crashes (TASK-621 fixed it?)".

### Decision 4: A deterministic sample per pull request, every mutant nightly

- **Context**: The corpus (the `.tt`/`.ttx` units of `tests/cases` and
  `tests/fixtures`, 69 today) has 54,441 mutants: every prefix at a
  character boundary and every single-character deletion.
- **Alternatives considered**: Every mutant in `cargo test` (about twelve
  minutes in a debug build); a random sample (a failure that does not
  reproduce cannot be bisected).
- **Decision and rationale**: `cargo test` runs 1000 mutants chosen by a
  fixed-seed Fisher-Yates draw (splitmix64, seed `0x74746d7574617465`),
  about 5 seconds in a debug build on four workers. `TT_MUTATIONS=all`
  runs every mutant, about 58 seconds in a release build, which the
  scheduled CI run does in a new `exhaustive` job; `TT_MUTATIONS=<n>` and
  `TT_MUTATION_SEED=<n>` choose another sample. A new crash is minimized
  (chunked deletion while the signature holds) and reported with the file
  name to save it under.

### Decision 5: cargo-fuzz runs briefly on its own nightly schedule

- **Context**: A fuzz finding depends on luck. CI's scheduled run publishes
  the Nightly only when it succeeds (`release-publish.yml`).
- **Alternatives considered**: A cargo-fuzz job in `ci.yml` (a lucky find
  would block a Nightly at random); no scheduled fuzzing.
- **Decision and rationale**: `Soak` gains a daily schedule that fuzzes each
  target for 120 seconds from the seeded corpus and the committed crash
  inputs; dispatching it keeps the 900-second default and the full corpus.
  The deterministic exhaustive mutation pass stays in `ci.yml`, where a
  failure is a reproducible regression on `main`. TASK-223 carries a note
  that its manual-only decision is superseded in part.

### Decision 6: Seed the fuzz corpus by content hash

- **Decision and rationale**: `scripts/fuzz-seed-corpus` writes each
  `.tt`/`.ttx` unit of `tests/cases` and `tests/fixtures` (split by
  `// @filename`, as the case runner does) to
  `fuzz/corpus/compile_any_bytes/<sha1>`, libFuzzer's own naming, so
  reruns write nothing new and the seed set is the same on every machine;
  `--list` prints each seed and its origin. `fuzz/corpus` stays ignored.

## Issues and resolutions

### Issue 1: A mixed-pattern match in a call argument is an internal compiler error

- **Symptom**: The mutation pass, from
  `tests/fixtures/emit/contextual-composed-match/input.tt`, found
  `e(match(f){e=>({d:""}),false=>({})})`, which panics in
  `src/codegen/core/emitter/pattern.rs` with "switch variant alternative is
  not constructor". `ttc --check` and `ttc -p` both report "internal
  compiler error" for
  `consume(match (flag) { e => 1, false => 2 });`, while the same match as a
  declaration's value reports `match-mixed-patterns`.
- **Cause**: Not investigated here; the `match-mixed-patterns` check does not
  stop lowering when the match is a call's argument.
- **Resolution**: Committed as
  `fuzz/regressions/compile_any_bytes/mixed-patterns-in-a-call-argument.tt`
  and listed under TASK-637 until a fix is planned. Reported.

### Issue 2: The two known internal compiler errors

- **Symptom**: `Rect(width) if };` (an arm whose guard is not written yet)
  panics in `src/parser/matches.rs` ("byte range starts at N but ends at
  N"); `result { const x = try r(); return \`v\`};` panics in
  `src/codegen/rope.rs` ("Result return start has no matching end").
- **Cause**: Known; fixed by TASK-621 and TASK-622, then on a paused branch.
- **Resolution**: Committed as `arm-guard-not-written.tt` and
  `result-return-template-literal.tt`, first listed under TASK-621 and
  TASK-622; after those tasks were merged the replay reported both as no
  longer crashing and the lines were removed, which is the list shrinking as
  designed. Neither shape occurs in the case corpus, so the mutation pass
  does not reach them; the committed inputs do.

### Issue 3: `fuzz/Cargo.lock` was stale before this task

- **Symptom**: `cargo check --manifest-path fuzz/Cargo.toml --all-targets
  --locked` (the `check` job's and `scripts/ci rust`'s last step) failed on
  the base commit: "cannot update the lock file ... because --locked was
  passed".
- **Cause**: `ttc` gained `unicode-width` without the fuzz lock file being
  refreshed.
- **Resolution**: The lock file now lists it; the check passes. The merge
  of TASK-621 to TASK-628 vendored `swc_ecma_ast` and `swc_ecma_visit` as
  path dependencies and left the fuzz lock file naming their registry
  sources, which failed the same check again; the lock file was refreshed
  after the merge.
